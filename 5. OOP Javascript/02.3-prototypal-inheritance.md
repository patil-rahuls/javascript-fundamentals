## OOP Javascript > Prototypes & Prototypal Inheritance

> 🎯 **Prototypes** allow you to define methods and properties on a single object (the prototype object) that are shared across all instances. This ensures methods are stored in memory only once, making your code efficient and fully leveraging the power of **Prototypal Inheritance**.

---
&nbsp;

### 1. The `prototype` Property

As seen earlier, placing a method directly inside a constructor function is a bad practice because every instance gets its own duplicate copy. To fix this, we use the `prototype` object. 

Every function in JavaScript automatically has a property called `prototype`. We attach our shared methods to this object.

```javascript
// Adding a method to the prototype
Student.prototype.show = function () {
  console.log(this.rollNo, this.name);
  // 'this' points to the instance calling the method
};

// Now all instances of Student have direct access to show()
stu.show();
```

*By using the prototype, there exists only one copy of the `show()` method in memory, but it is available to every single instance of `Student`.*

### 2. Checking Prototypes: `isPrototypeOf()`

It's crucial to understand that `Student.prototype` is **not** the prototype of the `Student` constructor function itself. It is the prototype of the *objects created* by that constructor. Think of it as `Student.prototypeOfLinkedObjects`.

We can verify this relationship using `isPrototypeOf()`:

```javascript
const s1 = new Student("Hitesh", 33);
const s2 = new Student("Aajesh", 28);
const s3 = new Student("Rahul", 28);

console.log(Student.prototype.isPrototypeOf(s1));
// true

console.log(Student.prototype.isPrototypeOf(s2));
// true

// It is NOT the prototype of the constructor function itself
console.log(Student.prototype.isPrototypeOf(Student));
// false
```

### 3. Adding Properties to the Prototype

We aren't limited to just methods; we can also set properties (state) on the prototype.

```javascript
Student.prototype.school = "KV INS HAMLA, MUMBAI";

console.log(s1.school);
// "KV INS HAMLA, MUMBAI"

console.log(s2.school);
// "KV INS HAMLA, MUMBAI"
```

*We can use `hasOwnProperty()` to check if a property lives directly on the object or if it's being inherited from the prototype:*

```javascript
// Checking the instance
console.log(s1.hasOwnProperty("name"));
// true (name was set directly inside the constructor)

console.log(s1.hasOwnProperty("school"));
// false 
// "school" is not the instance's own property; it lives on the prototype.
```

### 4. The `__proto__` Link

Every object in JavaScript has a hidden property called `__proto__` (often referred to simply as its prototype). When an object is instantiated, this `__proto__` property is directly linked to its constructor's `prototype` property.

```javascript
console.log(s1.__proto__ === Student.prototype);
// true
```

*Example: Putting it all together with a `Car` constructor:*

```javascript
const Car = function (make, speed) {
  this.speed = speed;
  this.make = make;
};

// Add methods to the prototype object of the constructor function
Car.prototype.accelerate = function () {
  this.speed++ && console.log(this.speed);
};

Car.prototype.brake = function () {
  this.speed-- && console.log(this.speed);
};

const BMW = new Car("BMW", 120);
const Mercedes = new Car("Mercedes", 95);

BMW.accelerate(); // 121
```

### 5. Extending Built-in Prototypes (Anti-Pattern)

Because built-in objects like `Array` or `String` use prototypal inheritance, you *can* technically add your own custom methods to `Array.prototype`. 

```javascript
Array.prototype.unique = function () {
  console.log(`Overriding inbuilt fn.`);
  return [...new Set(this)];
};

const arr = [3, 43, 8, 547, 58, 87, 8, 32, 21, 23, 75, 8, 8, 3, 2];

console.log(arr.unique());
// [3, 43, 8, 547, 58, 87, 32, 21, 23, 75, 2]
```

**⚠️ NOT RECOMMENDED:** You should avoid extending built-in prototypes. If a future JavaScript update introduces a native method with the exact same name (e.g., a native `Array.prototype.unique`), your code could break or behave unpredictably. Always rely on built-in functions or create utility functions instead.
