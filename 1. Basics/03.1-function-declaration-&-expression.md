## Function Declaration & Expression

> 🎯 
> *   **Function Declarations** are hoisted *before* any **var** declaration.
> *   **Function Expressions** are *not* hoisted (unless declared with **var**, in which case only the variable is hoisted, not the function assignment).

---
&nbsp;

## 1. Function Declaration
*   Always hoisted to the top of their scope.
*   Hoisted *before* any **var** variable initialization.

```javascript
function calcAge(birthYear) {
  return 2021 - birthYear;
}
```

## 2. Function Expression
*An expression is a piece of code that produces a value.*

In JavaScript, functions are treated as first-class objects _(callable objects)_. Because of this, we can write a function as an expression and assign it directly to a variable.

```javascript
const calcAge2 = function (birthYear) {
  return 2021 - birthYear;
};
```

&nbsp;

### 🧠 Exercise: Hoisting Priority

What will be the output of the following code?

```javascript
var show = function () {
  return "Hello";
};

function show() {
  return "World";
}

show();
```

**Output:** `"Hello"`

**Why?**
1.  The **Function Declaration** (`function show() { return "World"; }`) is hoisted *first*.
2.  Then, the **var** variable initializer (`var show = function() { return "Hello"; }`) is evaluated, which overrides the hoisted function declaration with the new function expression.
