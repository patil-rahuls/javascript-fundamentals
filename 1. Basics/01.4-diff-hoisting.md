## **let**, **const** & **var** - Hoisting

> 🎯 Difference 3 - Hoisting
> *   **var** variables are hoisted to the top of their scope and initialized with **`undefined`**.
> *   **let** & **const** variables are hoisted but remain *uninitialized* in the **Temporal Dead Zone (TDZ)** until their initialization is processed.
---
**Hoisting**: Behavior of variable and function declarations being moved to the top of their scope before the code executes.

&nbsp;

## 1. Hoisting with **var**
**var** variables are accessible in their enclosing function scope even before they are declared, but they will hold the value **`undefined`**.

```javascript
function foo() {
  console.log(x); // undefined

  var x = "Rahul";

  console.log(x); // 'Rahul'
}

foo();
```

## 2. Hoisting with **let** & **const** _(The TDZ)_
While **let** and **const** *are* hoisted, their value is **uninitialized**. From the start of the block until the declaration is evaluated, they reside in the **Temporal Dead Zone (TDZ)**. 

```javascript
function checkHoisting() {
  console.log(x); 
  // ❌ Uncaught ReferenceError: Cannot access 'x' before initialization

  let x = "Rahul";

  console.log(x); // 'Rahul'
  
  console.log(y); // undefined
  var y = 25;
}

checkHoisting();
```
---

## Why does the Temporal Dead Zone (TDZ) exist?

The primary purpose of the TDZ is to **identify bugs early and clearly**.

*   **Explicit Error Messages:** As seen in the example above, the TDZ throws a specific `ReferenceError` ("Cannot access before initialization"). This tells you *exactly* what went wrong.
*   **Prevents Silent Failures:** If `x` was declared using **var**, it would silently return `undefined`. This masks the real issue and leads to hard-to-track logic bugs later in the code.
*   **Enforces Best Practices:** It acts as a safeguard, forcing you to define variables *before* using them.
*   **Validates const:** The TDZ ensures that **const** variables work correctly by guaranteeing they throw an error if not strictly initialized upon declaration.
