## The **typeof** Operator

The **typeof** operator returns a string indicating the type of the unevaluated operand.


```javascript
console.log(typeof x);
// "undefined" (if x isn't defined)

console.log(typeof "arr");
// "string"

console.log(typeof 4);
// "number"

console.log(typeof true);
// "boolean"

// ⚠️ Special Cases: Not standard numbers, but evaluated as "number"
console.log(typeof NaN);
// "number"
console.log(typeof Infinity);
// "number"

const square = (num) => num * num;
console.log(typeof square);
// "function"

// ⚠️ Arrays and Objects share the same type
console.log(typeof [2, 4, 6]);
// "object"

console.log(typeof {});
// "object"

```
---

### Differentiating Arrays and Objects

Since **typeof** returns `"object"` for both Arrays and standard Objects, you can use **`Object.prototype.toString.call()`** to determine the exact structural type.

```javascript
// ✅ Array
const givenArray = [1, 2, 3];
Object.prototype.toString.call(givenArray); 
// '[object Array]'

// ✅ Object
const givenObject = { name: "Rahul", age: "25" };
Object.prototype.toString.call(givenObject); 
// '[object Object]'
```

### Type Validations *(Optional Read)*

```javascript
function isNumeric(str) {
  if (typeof str !== "string") {
    return false; // Only process strings
  }

  return !Number.isNaN(str) && !Number.isNaN(Number.parseFloat(str));
}
```

#### Why combine these checks?
*   **`Number.isNaN`** evaluates empty strings or whitespaces as valid (returns `false`).
*   **`Number.parseFloat`** / **`Number.parseInt`** strictly evaluate them as `NaN`.

```javascript
Number.isNaN("");        // false
Number.isNaN("   ");     // false

Number.parseInt("");     // NaN
Number.parseFloat("   ");// NaN
```

#### Global vs. Number Class Methods
You can technically use the global fallback methods:
You can technically use the global fallback methods:
```javascript
return !isNaN(str) && !isNaN(parseFloat(str));
```
#### *Why use `Number.*`?* 
These global functions exist from the earliest versions of JavaScript. In **ES6**, for better modularization, they were added to the **`Number`** class. 

Specifying the class _(e.g., **`Number.parseFloat`**)_ explicitly states your intention and follows modern coding standards.
