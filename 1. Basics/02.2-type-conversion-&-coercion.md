## Type Conversion and Coercion

> 🎯 
> *   **Type Conversion** is *explicit* (done intentionally via code).
> *   **Type Coercion** is *implicit* (done automatically by JavaScript).
---
&nbsp;

## 1. Type Conversion *(Explicit)*

```javascript
let age = 28;
console.log(typeof age); 
// "number"

age = "28"; 
// Explicitly converted/assigned as a string

console.log(typeof age); 
// "string"
```

## 2. Type Coercion *(Implicit)*

```javascript
let age = 28;
let str = "I am " + age; 
// During concatenation, "age" is implicitly coerced from "number" to "string".

console.log(typeof age); 
// "number" (The original variable remains unchanged)
```
---
&nbsp;

## The **`+`** Operator Rule
When an expression contains only **`+`** operators, if *one* of the operands is a string, all operands **after the FIRST string operand** are automatically coerced into strings.

```javascript
console.log("23" + "10" + 3);     // '23103'
console.log("23" + "10" + 3 + 5); // '231035'

console.log(4 + 1 + "5" + 6);     // '556' 
// (4+1 = 5, then hits string "5", making it "55", then "556")
console.log(1 + 3 + 5 + "5");     // '95'  
// (1+3+5 = 9, then hits string "5", making it "95")
```

### Other Mathematical Operators
All other math operations (e.g., **`-`**, **`*`**, **`/`**) work normally by automatically coercing strings *back to numbers*.

```javascript
console.log("23" - "10" - 3); // 10
console.log("23" + "10" - 3); // '2307' ("23"+"10" = "2310", then - 3 coerces it to number 2307)
```

### Type Coercion with Arrays *(Optional Read)*

> **Rule:** The **`+`** operator prefers strings if it can't find two numbers to add.

```javascript
let a = [1, 2, 3];
let b = a + 10;

console.log(b); // '1,2,310' (string)
```
*How it works:* JavaScript tries to convert the array into a primitive string by calling its **`toString()`** method. `[1, 2, 3].toString()` results in the string `"1,2,3"`. Then, string concatenation occurs: `"1,2,3" + 10` = `"1,2,310"`.

### Number Type Conversion

#### 1. Loose Conversion
Converts a string loosely by extracting a valid number from the **START** of the string. Returns **`NaN`** if the start isn't numeric.

**`Number.parseInt()`** - Extracts an *integer*:
```javascript
Number.parseInt("12");      // 12
Number.parseInt(12.345);    // 12
Number.parseInt("12.345");  // 12
Number.parseInt("aaa");     // NaN
Number.parseInt("");        // NaN
Number.parseInt("   ");     // NaN
Number.parseInt(" 2.3");    // 2
Number.parseInt("1   ");    // 1
Number.parseInt("foo2");    // NaN (Starts with non-number)
Number.parseInt("12a5");    // 12  (Stops extracting at 'a')

// Radix/Base parsing:
Number.parseInt("0x10");    // 16 (Considers '0x' as hex radix, returns decimal 16)
Number.parseInt("08");      // 8  (Parses as decimal or octal depending on runtime, usually 8)
```

**`Number.parseFloat()`** - Extracts a *floating-point* value:
```javascript
Number.parseFloat("12.345");    // 12.345
Number.parseFloat("12.345abc"); // 12.345
Number.parseFloat("abc12.345"); // NaN
Number.parseFloat("");          // NaN
Number.parseFloat("   ");       // NaN
Number.parseFloat(" 2.3");      // 2.3
Number.parseFloat("1   ");      // 1
Number.parseFloat("foo2");      // NaN
Number.parseFloat("12a5");      // 12
Number.parseFloat("0x10");      // 0 (Does not consider hex radix, stops at 'x')
```

#### 2. Strict Conversion
Converts a string fully to a number. It expects **all characters** in the string to be strictly numerical, otherwise it fails.

**`Number()`** - Strict conversion. Extracts both _integer_ or _floating-point_ value. Returns **`NaN`** if invalid:
```javascript
Number("12.345");    // 12.345
Number("12.345abc"); // NaN (Failed strict check due to 'abc')
Number("abc12.345"); // NaN
Number("");          // 0   (Empty string coerces to 0)
Number("   ");       // 0   (Whitespace coerces to 0)
Number(" 2.3");      // 2.3
Number("1   ");      // 1
Number("foo2");      // NaN
Number("12a5");      // NaN
Number("0x10");      // 16  (Hex string strictly parsed)
```
