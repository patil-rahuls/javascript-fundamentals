## Asynchronous Javascript > Promises [ES6]

> 🎯 A **Promise** is an object that serves as a placeholder for the future result of an asynchronous operation (like a response from an AJAX call). It provides a powerful and elegant way to handle asynchronous code, allowing you to chain operations and escape "callback hell" without relying on deeply nested callbacks.

---
&nbsp;

### 1. Introduction to Promises using `fetch()`

A common way to interact with Promises is by using the modern `fetch()` function to make network requests. `fetch()` immediately returns a Promise object.

```javascript
const result = fetch("[https://xyz.com/api/somedata](https://xyz.com/api/somedata)");

console.log(result);
// Promise {<pending>}
```

In this example, the Promise is in a `<pending>` state, meaning the data is currently being fetched in the background. If the request completes successfully, the state will eventually change:

```text
// Later, once the background request has completed:
Promise {<fulfilled> : Response}
```

### 2. Definitions & Advantages

*   **Formal Definition:** An object that is used as a placeholder for the future result of an asynchronous operation.
*   **Informal Definition:** A container for a value that will be delivered asynchronously in the future (simply "a container/placeholder for a future value").

The main advantage of this pattern is that we don't need to rely on events and callbacks passed into asynchronous functions to handle results. Instead of nesting callbacks, we can smoothly chain Promises for a sequence of asynchronous operations.

### 3. The Promise Lifecycle

Because Promises work with asynchronous operations, they are time-sensitive and change their state over time.

1.  **Pending:** The initial state (before the value is available).
2.  **Settled:** The state when the asynchronous task has finished executing (regardless of success or failure).
3.  **Fulfilled:** The state when the task was successful and the value is now available (occurs after the 'Settled' state).
4.  **Rejected:** The state if an error occurred during the task (occurs after the 'Settled' state).

> ⚠️ **Important Terminology:** Working with Promises generally involves two phases. First, we **"Build a Promise"** (create it and define its asynchronous task). Then, we **"Consume a Promise"** (handle the fulfilled value or rejected error).
