## Asynchronous Javascript > Building a Promise

> 🎯 A **Promise** is an object used as a placeholder for the future result of an asynchronous operation. You can construct your own promises to handle custom asynchronous logic or to wrap older callback-based functions into modern, chainable structures.

---
&nbsp;

### 1. Creating a New Promise

You create a new promise using the `Promise` constructor. It takes exactly one argument: the **executor** function. This executor function automatically receives two parameters:

*   **`resolve( <to be fulfilled value> )`**
*   **`reject( <rejection reason> )`**

```javascript
const myPromise = new Promise((resolve, reject) => {
  let dataReceived = true; // Simulating a condition

  // ... some asynchronous operation here ...
  // that updates 'dataReceived' to true or false

  if (dataReceived) {
    // Fulfill the promise if 'dataReceived' is true.
    resolve("Data fetched successfully!");
  } else {
    // Reject the promise if 'dataReceived' is false.
    reject("Failed to fetch data.");
  }
});
```

In the example above:
*   Calling `resolve("Data fetched successfully!")` sets the Promise state to **fulfilled**. The passed string will be available as the fulfilled value.
*   Calling `reject("Failed to fetch data.")` sets the Promise state to **rejected**. The passed string will be available as the rejection reason.

### 2. Consuming the Promise

You consume the output of a Promise using the `.then()` and `.catch()` methods.

```javascript
myPromise
  .then((result) => console.log(result))
  .catch((err) => console.error(err));

// Output (if fulfilled):
// 'Data fetched successfully!'
```

The callback inside `.then()` executes when the promise resolves, and its parameter (`result`) holds the **fulfilled value**. The callback inside `.catch()` executes when the promise rejects, and its parameter (`err`) holds the **rejection reason**.

### 3. Promisifying

**Promisifying** means converting callback-based asynchronous behavior into promise-based behavior. This allows you to use `.then()` chains or `async/await` instead of nested callbacks.

```javascript
// Example: Promisifying setTimeout()
const waitForNSecond = function (seconds) {
  return new Promise(function (resolve) {
    setTimeout(resolve, seconds * 1000);
  });
};

// Using an arrow function (more concise):
const waitForNSeconds = (seconds) =>
  new Promise((resolve) => setTimeout(resolve, seconds * 1000));

// Usage:
waitForNSeconds(4)
  .then(() => {
    console.log("I waited for 4 Seconds.");
    
    // We return the new promise to chain it properly
    return waitForNSeconds(1); 
  })
  .then(() => {
    console.log("I waited for another 1 Second.");
  });
```

> ⚠️ **Important:** By returning a new promise inside the `.then()` method and chaining subsequent `.then()` methods, we completely avoid "callback hell" and keep our code flat and readable.

### 4. Immediate Resolution or Rejection

If you need a promise that instantly resolves or rejects, you can use the built-in static methods:

```javascript
Promise.resolve('abc')
  .then((x) => { console.log(x) }); 
// Outputs: 'abc'

Promise.reject(new Error('something failed'))
  .catch((err) => { console.log(err) }); 
// Outputs: Error: something failed
```
