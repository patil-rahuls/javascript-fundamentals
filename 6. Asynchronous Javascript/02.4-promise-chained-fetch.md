## Asynchronous Javascript > Chained Promises & Error Handling [ES6]

> 🎯 Chaining promises allows you to execute asynchronous operations sequentially where each step depends on the output of the previous one. However, managing error states across a long chain requires proper error handling strategies like `.catch()` and `.finally()`.

---
&nbsp;

### 1. Chaining Multiple Asynchronous Requests

You can chain multiple fetch requests by returning a new promise from inside a `.then()` callback.

```javascript
const getData = (page) => {
  fetch(".../api/users?page=" + page)
    .then((response) => response.json())
    .then((data) => {
      const input2 = data[0];
      if (!input2) {
        return;
      }

      // Return a new promise to chain the next fetch request
      return fetch(".../api/somedata/" + input2);
    })
    .then((response) => response.json())
    .then((data) => console.log(data));
};

getData(2);
```

---

### 2. Handling Rejected Promises

When a promise in a chain fails, you need a mechanism to catch and handle the error.

#### The "Noob" Way (Repeating `.then()` Handlers)
Every `.then()` method accepts two arguments: one for fulfillment and one for rejection. Manually passing a rejection handler to every single `.then()` leads to repetitive, cluttered code.

```javascript
const getDataErrHandled = (page) => {
  fetch(".../api/users?page=" + page)
    .then(
      (response) => response.json(),
      (err) => console.error(err)
    )
    .then(
      (data) => {
        const input2 = data[0];
        if (!input2) {
          return;
        }
        return fetch("[https://xyz.com/api/somedata/](https://xyz.com/api/somedata/)" + input2);
      },
      (err) => console.error(err)
    )
    .then(
      (response) => response.json(),
      (err) => console.error(err)
    )
    .then(
      (data) => console.log(data),
      (err) => console.error(err)
    );
};

getDataErrHandled(2);
```

#### The "Smart" Way (Using `.catch()`)
Instead of cluttering every `.then()`, you can place a single `.catch()` method at the very end of the promise chain. It will automatically intercept and handle any error thrown at any stage of the chain.

```javascript
const getDataWithCatch = (page) => {
  fetch(".../api/users?page=" + page)
    .then((response) => response.json())
    .then((data) => {
      const input2 = data[0];
      if (!input2) {
        return;
      }
      return fetch(".../api/somedata/" + input2);
    })
    .then((response) => response.json())
    .then((data) => console.log(data))
    .catch((err) => console.error(err.message));
  // Every Error object has a property called 'message'.
};

getDataWithCatch(2);
```

### 3. The `.finally()` Method

The `.finally()` method is always executed at the end of the promise chain, regardless of whether the promise was fulfilled or rejected. This makes it ideal for cleanup tasks (like hiding loading spinners).

```javascript
const getDataWithFinally = (page) => {
  fetch(".../api/users?page=" + page)
    .then((response) => response.json())
    .then((data) => {
      const input2 = data[0];
      if (!input2) {
        return;
      }
      return fetch(".../api/somedata/" + input2);
    })
    .then((response) => response.json())
    .then((data) => console.log(data))
    .catch((err) => console.error(err.message))
    .finally(() => {
      // Always executes
      hideLoadingSpinner();
      // Useful to hide the loading indicator 
      // after the asynchronous operation is complete.
    });
};
```

### 4. Manually Rejecting Promises by Throwing Errors

> ⚠️ **Important:** A crucial quirk of `fetch()` is that server error status codes like **404** or **500** are **not** treated as rejections. The promise still resolves successfully because the server responded. To catch these as errors, you must manually inspect `response.ok` and throw an error.

```javascript
const getDataWithManualReject = (page) => {
  fetch(".../api/users?page=" + page)
    .then((response) => {
      console.log(response.status); // e.g., 404

      if (!response.ok) {
        // The 'ok' property is true if status is 200–299, and false otherwise.
        throw new Error("Failed with status: " + response.status);
        // Throwing an error immediately rejects the promise,
        // causing execution to skip down directly to the .catch() block.
      }

      return response.json();
    })
    .then((data) => {
      const input2 = data[0];
      if (!input2) {
        return;
      }
      return fetch(".../api/somedata/" + input2);
    })
    .then((response) => response.json())
    .then((data) => console.log(data))
    .catch((err) => console.error(err.message))
    .finally(() => {
      hideLoadingSpinner();
    });
};

getDataWithManualReject(2000);
```
